# Build a Web-Based Farmer Dashboard for My Mobile App

Create a modern, responsive **web-based dashboard UI** that works as the companion web interface for my existing mobile application.

The web dashboard must use **Firebase Authentication** and **Firebase Realtime Database** as the backend.

## 1. Main Goal

Build a web application where an authenticated farmer can monitor and control the farming system from a desktop or mobile browser.

The web dashboard should use the **same Firebase Realtime Database** used by my mobile application so that changes made from the web dashboard are reflected in the mobile app and vice versa.

Do NOT create a separate database.

---

# 2. Firebase Realtime Database

The existing database contains these main paths:

```text
/system
/feedingSchedules
/rinseSchedules
/manualControl
/logs
/notifications
```

The application must read and write data using these paths according to the Firebase security rules.

Do not invent unnecessary database paths.

Before implementing database operations, inspect the existing project and determine the actual data structure where possible.

---

# 3. Authentication

Implement Firebase Authentication.

The farmer must log in before accessing the dashboard.

Create:

* Login page
* Logout functionality
* Authentication state checking
* Protected dashboard routes
* Loading state while Firebase checks authentication

Unauthenticated users must be redirected to the login page.

Authenticated users can access the dashboard.

Do not store passwords manually in Realtime Database.

Use Firebase Authentication.

# 14. Firebase Configuration

Do not hard-code sensitive credentials directly into source files.

Use environment variables/secrets.

Create configuration using variables such as:

```text
VITE_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN
VITE_FIREBASE_DATABASE_URL
VITE_FIREBASE_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET
VITE_FIREBASE_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID
```

If the existing Replit project already has Firebase configuration, inspect and reuse it rather than creating duplicate configuration.

IMPORTANT:

Never put Firebase Admin SDK private credentials or service-account private keys in frontend code.
